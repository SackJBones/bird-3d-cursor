## Feasibility and source-backed constraints

Checked against official pages on 2026-09-18/19; revisit before implementation if SDK capabilities change.

1. VRChat creator projects currently require **Unity 2022.3.22f1**, not an arbitrarily newer editor. General-purpose Bird must have a separate current, patched Unity validation matrix. [Supported editor](https://creators.vrchat.com/sdk/upgrade/current-unity-version/).
2. Udon exposes avatar bone positions; missing bones return zero. Tracking data exposes local head/hand transforms, not the full OpenXR joint stream. Humanoid distal bones are not tracked fingertip endpoints. A world adapter needs explicit joint mapping, fingertip estimation/calibration, tracking-quality handling, scale handling, and in-headset evidence. Do not claim raw tracked-hand equivalence. [Player positions](https://creators.vrchat.com/worlds/udon/players/player-positions/).
3. Portable Items exist, but the current official FAQ says user-created Items are unsupported. The exact in-world acquisition of arbitrary cross-world Bird is therefore a **platform gate**, not a promised deliverable. [Items FAQ](https://help.vrchat.com/hc/en-us/articles/45059565610387-Items-FAQ). World Udon also cannot reference Items: [Items in worlds](https://creators.vrchat.com/worlds/items/).
4. Avatar components are allowlisted; the existing C# Bird runtime cannot simply be attached to an uploaded avatar. Investigate animator/constraint/contact implementations separately, measure fidelity, and label approximations. A public Bird-equipped avatar could provide a no-code avatar-switching route, but is not an attachment to the user's existing avatar and does not itself solve sphere fitting. [Allowed components](https://creators.vrchat.com/avatars/whitelisted-avatar-components/whitelisted-avatar-components/), [avatar cloning](https://docs.vrchat.com/docs/public-avatar-cloning).

## Stages and acceptance criteria

- [x] Discover repositories, preserve transcript, establish feature branches and initial code checkpoint.
- [x] Establish recurring app task; verify a real scheduled pass can read/write, run tests and push. Record its run evidence separately from manual testing.
- [ ] Audit math, click hysteresis, invalid/degenerate poses, tracking loss/recovery, coordinate spaces and allocation behavior. Add deterministic recorded/synthetic pose tests, preserving reference behavior unless an intentional change is documented.
- [ ] Modernize packaging: isolated core, optional tracking adapters, correct runtime/editor assembly boundaries, stable GUIDs, minimal dependencies, clear installation and migration instructions. Fresh-project import and player build must pass. Replace DOTween dependency with small owned state-transition tools where relevant, not copied third-party internals.
- [ ] Install VRChat-supported editor/Creator Companion SDK and create a minimal hand-data feasibility world. Prove two-hand cursor/click behavior with real hardware before making a polished world. Provide a clearly labeled controller/desktop fallback where true joint input is unavailable.
- [ ] Bird World: automatic or single-action activation, good defaults, two cursors, visible trails, a few delightful interactions and accessible conventional configuration. Test remote visibility, late join, ownership, rejoin, tracking loss and avatar changes on PC and Android/Quest.
- [ ] Expression: bounded fading trails, mandala duplication with live multiplicity/clear controls, fireball and recovered dodecahedral color picker. Profile memory/render cost and prevent unbounded allocations, geometry and network traffic.
- [ ] Rich UI: composable interaction/state styling, hover/point-through/plunge/click events, tweened affordances, nested menus and Bird-driven settings alongside conventional settings. Prefer composition unless inheritance provides concrete value.
- [ ] Portable Bird gate: test supported avatar approach and document fidelity/limits; re-evaluate creator Items access. Do not mark the original adoption flow complete while this gate remains unmet.
- [ ] Release polish: reproducible demos, fresh install docs, free baseline UI, contribution guide, license audit, versioned package, CI and Unity compatibility evidence. Prepare Asset Store delivery; do not claim an uploaded or approved listing without evidence.
- [ ] Once core is proven, consider Unreal/Godot/AR integrations on descendant branches. Do not expand into these to avoid an unresolved core task.
